05 关键交互流程

5.1 报警处置闭环

规则命中 → 生成事件（OPEN）→ 消息中心按级别路由
   ├─ 飞书卡片【认领】→ 回写 ACK → 其他端 5s 内同步
   ├─ 小程序列表点击 → 认领 → 填处置说明
   └─ 15 分钟未认领 → 升级主管 → 30 分钟 → 管理员 + 短信
处置方式三选一：
   ① 生成维修工单（跳任务创建，预填站房/类型/来源=报警）
   ② 标记误报（填原因 → 回流到规则优化清单）
   ③ 转派他人（选人 + 备注）
关闭条件：必须有处置说明；涉及数据的必须附现场照片或核查结论

5.2 运维作业闭环（小程序）

主管排计划 → 自动生成任务 → 下发
  → 工程师接单（计时开始）
  → 出发（可选导航）
  → 到场打卡（定位 + 人脸，≤300m）
  → 扫站房码（校验任务匹配）
  → 按模板填报（离线可缓存）
  → 拍照 / 领用物资 / 校准数据录入
  → 签名提交
  → 主管审核（通过 / 驳回填原因）
  → 归档 + 生成运维台账 + 触发下一次计划建议

5.3 数据 → 工单下钻

原始数据页发现异常（如恒值 13 分钟）
  → 选中区间 → 右键/按钮"生成异常工单"
  → 弹窗预填：站房、因子、时间区间、异常描述、证据截图
  → 指派工程师 → 任务来源标记 ALARM/MANUAL
  → 处理完成后，工单与数据区间双向关联，审计可查

5.4 计划排期

选择月份 → 系统按规则生成草稿（站房类型 × 运维类型 × 周期）
  → 日历展示：已排（蓝）/ 未排（橙）/ 冲突（红）
  → 点"未计划"数字 → 下钻缺口清单 → 批量勾选 → 一键排期
  → 提交审批 → 生效 → 到期自动生成任务

06 通用组件规范

6.1 四段式筛选器（全局复用）

段行为
区域级联选择，默认取用户数据权限范围
企业依赖区域，支持搜索；选"全部"则不限
站房依赖企业，显示"站房名 + 类型"；支持多选
类型 / 状态按页面语义变化（运维类型/报警级别/设备类别）

规则：上一级变更自动清空下一级；筛选条件写入 URL query，便于分享与刷新保持；"查询"与"重置"固定右侧。

6.2 状态标签

类型取值与文案
站房业务态正常 / 异常 / 停运 / 维护
任务状态待接单 / 已接单 / 到场 / 待审核 / 已完成 / 已退回 / 已超期
记录状态草稿 / 待审核 / 已通过 / 已驳回
报警状态待处理 / 处理中 / 已关闭 / 误报
设备联网已注册 / 已激活 / 已确认 / 未确认

6.3 因子透视表

  • 行 = 时间（倒序，固定首列），列 = 因子（可勾选、可拖拽排序、可冻结前 3 列）。
  • 每个因子单元格显示"值 + 标记"，非 N 标记用底色块，N 淡化显示。
  • 顶部固定工具条：时间快捷、因子选择、标记开关、曲线开关、导出。
  • 超过 8 因子时横向滚动，表头与首列双向吸顶。

07 空态、异常态与权限态

场景表现
无数据插画 + 一句说明 + 主动作（如"去添加计划"），不要只显示"暂无数据"
无权限显示"无访问权限"并说明需要的角色，不隐藏菜单（隐藏会让用户以为系统坏了）
加载失败错误码 + 重试按钮 + 复制错误 ID
数据延迟顶部黄条"数据更新于 14:20，延迟 3 分钟"
离线（小程序）顶部红条"当前离线，填报内容将本地保存"，提交按钮改为"保存待提交"
长时间无操作30 分钟提示，60 分钟自动登出

08 原型优先级

批次页面目的
第一批W02 工作台、W09 数字站房、W10 原始数据、W23 运维计划给甲方看"系统长什么样"，定视觉与信息密度
第二批W26/W27 任务、W29 记录审核、M03–M09 小程序作业流验证运维闭环是否顺手，这是能否落地的关键
第三批W20/W21 报警、W18 联网监测、W43 数据分析支撑监管汇报与考核
原型交付建议

用 Figma 或即时设计做可点击原型，优先把"计划 → 任务 → 执行 → 审核"这条主线串成可演示的完整流程。甲方评审时最容易被"点得动"打动，静态截图的说服力差很多。
