建议的评审顺序

  1. 先看 01 的第 3、4 节（角色 + 证据链）——这两个决定系统形态，其他都是细节。
  2. 再看 05 的页面清单——对照参考平台，确认有没有漏模块、多余模块。
  3. 然后 03 的接入方案——技术风险最集中的部分，特别是数据源到底是自建接入还是对接上级平台。
  4. 最后 02 和 04——实施阶段的依据，评审时可略过细节。
三项已全部确定

✅ 系统主体 = 监管方（多租户，运维单位入驻）；✅ 数据源 = 直连数采仪（自建 Netty 接入，原始报文/标记/参数/反控全部可用）；✅ 微信 = 已认证服务号「海兰天澄」（成都海兰天澄科技股份有限公司）+ 公网部署。详见 ADR。

代码工程

可运行骨架在仓库根目录：server/（NestJS）、web/（Vue3）、deploy/docker-compose.yml。启动方式见根目录 README.md。

  • server/src/common/ — 多租户上下文、JWT 鉴权、角色守卫、统一响应/异常、审计拦截器
  • server/src/modules/ingest/ — HJ212 拆包 / CRC16 / 编解码 / TCP 服务 / HTTP 入口（已通过 14 项运行时校验）
  • server/src/database/ — 实体、种子数据（admin / Admin@123）
  • web/ — 登录、主框架、工作台、站房列表
