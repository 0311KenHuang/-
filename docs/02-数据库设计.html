01 设计原则

原则说明
三库分离业务数据入 MySQL；分钟/小时数据入 TDengine；照片、谱图、视频入 MinIO。任何大字段都不进 MySQL。
多租户行级隔离所有业务表带 tenant_id，MyBatis 拦截器自动注入；跨租户查询仅超管可用且强制记审计。
纵向存数据监测数据按 (station_id, factor_code, ts) 纵向存储，新增因子零改表；前端按因子透视。
双维度标记dev_flag（设备标记 N/D/C/M/T/Td）与 prod_flag（工况标记）分列，绝不合并成"有效/无效"。
只追加审计sys_audit_log 只允许 INSERT，数据库层用触发器/权限禁止 UPDATE、DELETE。
软删除 + 乐观锁业务表统一 deleted、version；物理删除仅超管脚本执行。
快照留痕参数、限值、合同等"会变但需追溯"的数据，变更时写快照表，不回改历史。
编码可读站房、设备、报警、整改单均使用业务可读编码（如 FHZY-S-01），便于现场沟通与工单引用。

05 时序库设计

TDengine 采用"超级表 + 子表"模型：一个站房一张子表，按天分区。写入走 INSERT INTO ... USING ... TAGS 自动建表。

5.1 分钟数据超级表

CREATE STABLE IF NOT EXISTS ts_data_minute (
  ts          TIMESTAMP,        -- 数据时间
  value       DOUBLE,           -- 数值
  dev_flag    NCHAR(4),         -- 设备标记 N/D/C/M/T/Td
  prod_flag   NCHAR(4),         -- 工况标记 N/St/Sd/B/F
  raw_value   DOUBLE,           -- 原始信号值
  quality     TINYINT           -- 0 未知 1 有效 2 无效 3 未标记
) TAGS (
  station_id  BIGINT,
  station_code NCHAR(32),
  factor_code NCHAR(16),
  unit        NCHAR(16),
  tenant_id   BIGINT
);

5.2 存储与查询权衡

决策方案理由
一级标签station_id + factor_code90% 查询按"站房+因子+时间"
分区按天（KEEP 365）配合"在线 12 个月"要求
预聚合小时/日表由定时任务生成报表不扫明细，避免全表聚合
乱序写入允许（补传场景）TDengine 天然支持乱序，注意设置 KEEP 与 DURATION
去重唯一约束 (ts, station, factor) + 幂等写补传会重复上报，必须幂等

对象策略

07 关键 SQL 口径

7.1 小时有效率（附录 G）

-- 某站房某因子某小时：有效分钟数、有效率、是否有效（≥45 分钟）
SELECT
  station_id,
  factor_code,
  TO_TIMESTAMP(ts / 3600000 * 3600) AS hour_ts,
  COUNT(*)                                        AS total_min,
  SUM(CASE WHEN dev_flag = 'N' THEN 1 ELSE 0 END)  AS valid_min,
  ROUND(SUM(CASE WHEN dev_flag = 'N' THEN 1 ELSE 0 END) / 60.0, 4) AS valid_rate,
  CASE WHEN SUM(CASE WHEN dev_flag = 'N' THEN 1 ELSE 0 END) >= 45
       THEN 1 ELSE 0 END                          AS hour_valid
FROM ts_data_minute
WHERE station_id = ? AND factor_code = ?
  AND ts >= ? AND ts < ?
GROUP BY station_id, factor_code, hour_ts;

7.2 日有效率

-- 日均值有效条件：有效小时数 ≥ 75%（18 小时）
SELECT
  COUNT(*)                                        AS total_hour,
  SUM(hour_valid)                                 AS valid_hour,
  ROUND(SUM(hour_valid) / 24.0, 4)                AS day_valid_rate,
  CASE WHEN SUM(hour_valid) >= 18 THEN 1 ELSE 0 END AS day_valid,
  AVG(CASE WHEN hour_valid = 1 THEN avg_value END)  AS day_avg
FROM ts_data_hour
WHERE station_id = ? AND factor_code = ?
  AND ts >= ? AND ts < ?;

7.3 标记 ⇄ 工单 核验

-- 正向：标记了 C/M/D 但找不到对应运维记录（疑似虚假标记）
SELECT m.station_id, m.factor_code,
       DATE_FORMAT(m.ts, '%Y-%m-%d %H:%i') AS mark_time,
       m.dev_flag
FROM (
  SELECT station_id, factor_code, ts, dev_flag
  FROM ts_data_minute
  WHERE dev_flag IN ('C','M','D')
    AND ts >= ? AND ts < ?
) m
LEFT JOIN ops_record r
  ON  r.station_id = m.station_id
  AND r.status = 'APPROVED'
  AND m.ts BETWEEN r.mark_begin AND r.mark_end
WHERE r.id IS NULL
ORDER BY m.ts DESC;

7.4 计划覆盖率

-- 本月应运维站房 vs 已排期站房
SELECT
  COUNT(DISTINCT s.id)                                  AS should_plan,
  COUNT(DISTINCT p.station_id)                          AS planned,
  ROUND(COUNT(DISTINCT p.station_id) / COUNT(DISTINCT s.id), 4) AS coverage
FROM md_station s
LEFT JOIN ops_plan p
  ON p.station_id = s.id AND p.period = ? AND p.status IN ('APPROVED','DONE')
WHERE s.deleted = 0
  AND s.biz_status IN ('NORMAL','ABNORMAL')
  AND s.ops_org_id = ?;
